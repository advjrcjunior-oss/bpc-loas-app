## 2025-01-20 - Connection Pooling & Response Caching Optimization
**Learning:** External API dependencies in batch processing workflows (like LegalMail, ViaCEP, and CPF/CNPJ APIs) create severe N+1 bottlenecks and excessive TCP handshake overhead when unoptimized. `functools.lru_cache` cannot be directly applied to functions like `validar_cep` that return `None` on transient failures, nor to functions whose returned dictionaries are mutated downstream (e.g., `consultar_cpf`), as this permanently caches failures or corrupts the cache state.
**Action:** Use `requests.Session()` globally to maintain TCP keep-alive (connection pooling) for external API calls, reducing latency without caching risks. For strict rate-limited APIs (like LegalMail), use targeted instance-level caching (like `_options_cache`) to avoid redundant lookups.
