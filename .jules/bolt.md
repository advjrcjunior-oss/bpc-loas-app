## 2024-07-13 - Batch API Lookup Bottlenecks and Caching Pitfalls
**Learning:** During batch processing workflows (like legal document validation), making repeated isolated requests to external APIs (e.g., cpfcnpj.com.br, ViaCEP) causes severe bottlenecks due to overhead from repeated TLS handshakes. Furthermore, using `@functools.lru_cache` directly on API functions that return dictionaries (like `consultar_cpf` or `consultar_cnpj`) is dangerous because downstream functions (e.g., `validar_dados_cliente`) may mutate these dictionaries, leading to cache corruption. Caching functions that suppress exceptions to return `None` also risks permanently caching transient network failures.
**Action:** Always utilize `requests.Session()` to enable connection pooling (TCP keep-alive) for external REST API interactions, particularly in batch processing operations. Avoid using `lru_cache` on functions that return mutable objects or potentially mask network errors; rely on connection pooling to improve performance safely instead.
