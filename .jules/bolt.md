## 2024-05-18 - Connection pooling instead of unbounded cache for REST APIs
**Learning:** During batch processing workflows, utilizing `requests.Session()` for connection pooling is preferable to using `@functools.lru_cache` on API functions that return `None` on transient failures (e.g. `validar_cep`). Caching functions that catch network failures can result in permanently caching a failure state. Furthermore, returning mutable dictionaries from a cached function (like `consultar_cpf`) leads to cache corruption when downstream processes modify the returned dict.
**Action:** Always use `requests.Session()` to reuse TCP/SSL connections for REST APIs (ViaCEP, cpfcnpj) in batch scripts to improve throughput without the risks associated with in-memory memoization of dynamic or mutable API responses.
